# Inline-меню и отзывчивость

Главный экран — список аккаунтов (8 на страницу) и добавление. Имя задаётся в боте и меняется
в настройках; технический идентификатор остаётся стабильным для файлов сессий и истории.
Открытие аккаунта читает сохранённые данные PostgreSQL, не обращаясь в Маркет.
Daily и игровые награды запускаются разными кнопками. История, статистика, настройки и подключение вынесены отдельно.
Вложенные разделы имеют кнопку возврата.

Оформление следует игровым экранам reference-бота: жирный заголовок с emoji, цитата с
подписанными значениями, курсивные пояснения. Инструкция подключения и записи истории
раскрываются через `<blockquote expandable>`. Ошибка и следующее действие остаются видимыми.
Пользовательские имена экранируются; общие фрагменты не создают вложенных цитат.

Для просмотра настоящих значков выполните `make emoji-preview` при заполненном `.env`.
Откройте `.secrets/emoji-preview/tgiosicons/index.html` в браузере. Скрипт получает пак через
getStickerSet, закреплённые ID через getCustomEmojiStickers и скачивает миниатюры через Bot API.
Каталог содержит изображение, ID и ссылку на emoji в Telegram; это статические миниатюры,
не воспроизведение анимации. Сообщения ботом не отправляются, токен в HTML не записывается.
В reference-проекте найдены примеры разметки и ID, но готовый инструмент предпросмотра не найден.

Сбор, баланс и проверка входа сразу показывают loading-экран. Навигация временно блокируется,
повторные callback получают короткое уведомление и не выполняются после завершения как очередь.
Итог или ошибка заменяет loading-экран и возвращает кнопки. Callback подтверждается отдельно от HTTP.

Причина прежней общей задержки: handle_as_tasks=False последовательно ожидал полный сбор
перед обработкой следующего update. Включена ограниченная параллельность (16),
active updates отслеживаются и дожидаются завершения перед закрытием ресурсов.
Синхронный Market HTTP остаётся в thread; лимит запросов сохраняется.
Проверка баланса больше не читает один баланс дважды. Длительность реальных запросов не измерена здесь.

ScreenService редактирует активное сообщение, подавляет устаревшие результаты, восстанавливает
удалённое сообщение и обрабатывает Telegram «message is not modified».
NavigationIsolation сериализует короткие переходы/FSM, не удерживая mutex на время Market HTTP;
отдельный busy-флаг блокирует новые действия до результата. Повторное имя не создаёт второй аккаунт.

Ошибки показываются понятным текстом и следующим действием; None/failed/ProtocolError в UI отсутствуют.
При отсутствии свежего баланса отображается последнее значение из этой операции, без выдуманного
нулевого результата. Ошибки логируются по типу; ответы Маркета и credentials не выводятся в Telegram.

Добавление в боте создаёт запись и имя. Вход выполняется через QR/ссылку Яндекса,
после проверки API пользователь сохраняет сессию. Cookies не пересылаются через бот.
[Протокол QR-входа](bot-auth-research.md).

Пак [Telegram iOS Icons](https://t.me/addemoji/tgiosicons) получен через
[getStickerSet](https://core.telegram.org/bots/api#getstickerset) и локальный экспорт 29.10.2026:
399 уникальных эмодзи, включая закреплённые владельцем. Миниатюры просмотрены при подборе.
Выбранные ID сохранены в `src/services/emoji.py` (`PACK_ICONS`); startup больше не делает
getStickerSet. Одинаковые Unicode-метки в паке принадлежат разным изображениям, поэтому
автоматическое сопоставление по метке удалено. Экспорт нужен только для пересмотра дизайна,
на VPS каталог миниатюр не требуется.
Для [custom emoji](https://core.telegram.org/bots/api#formatting-options) Telegram требует
соответствующего права бота (Premium владельца или дополнительное имя Fragment).
При явном отказе Telegram интерфейс повторно отправляется без custom emoji.
Нативное отображение в Telegram после изменения в среде агента не проверялось.

Предоставленные владельцем ID имеют приоритет над автоопределением:
переименование `6050847684355428245`, история `5775896410780079073`, подключение `5895364284782743985`.
Время награды и запланированного запуска выводится через HTML `<tg-time unix="..." format="dT">`;
для отсчёта используется `format="r"`, для истории — `dt`. Форматы проверены по
[документации Telegram](https://core.telegram.org/bots/api#date-time-entity-formatting).
Текст внутри тега содержит дату UTC для fallback; обновляемые метки отображает Telegram, бот
не отправляет ежесекундные edit-запросы ради отсчёта.

На iOS замечено смещение границ цитаты/курсива рядом с динамическим временем
(на desktop владелец проблемы не наблюдал). В карточке и настройках цитаты сохранены:
внутри стоят абсолютные даты `<tg-time format="dT">`, локализуемые Telegram по часовому
поясу пользователя. Относительный отсчёт `format="r"` и отметка обновления баланса вынесены
за пределы цитат и не обёрнуты курсивом. Привязки к МСК нет. Это обход предполагаемой
проблемы сочетания относительного времени с форматированием; рендер на iOS после
этого изменения ещё требует проверки.

Ежедневный сбор и игровые награды разделены: кнопка «Ежедневная награда» и date-job
вызывают только daily API; отдельная кнопка «Игровые награды» собирает уже заработанные
игровые награды. Игровой запуск имеет отдельную запись истории с trigger=games и не
пересчитывает расписание дейли. Общие ограничения аккаунта (истечение сессии, rate limit,
неопределённый результат начисления) по-прежнему могут остановить автосбор ради безопасности.
Недоступная ежедневная награда — нормальный результат unavailable, не ошибка.
Ответ ручного запуска и уведомление включают результаты этапов именно этого run_id.

Диагностика прошлого запуска: `make diagnose-run RUN=<UUID>` читает PostgreSQL в READ ONLY
транзакции и сохраняет `.secrets/diagnostics/<UUID>.json`. В отчёте только метаданные запуска,
состояния операций и текущее расписание аккаунта, без токенов, паролей и cookies.
Текущее расписание не является снимком состояния на момент исторического запуска.

В настройках есть «Удалить аккаунт» с custom emoji корзины и ButtonStyle.DANGER.
Первое нажатие показывает вопрос с именем и последствиями: удаляются запись, история,
снимки баланса и рабочий файл сессии бота; аккаунт Яндекса не удаляется.
Подтверждение — красная «Да, удалить» с галочкой, отмена — зелёная «Нет, оставить»
со стрелкой назад. Все значки взяты из локального экспорта tgiosicons.
FSM привязывает одноразовое подтверждение к аккаунту, сообщению и nonce; отмена,
другой переход или рестарт аннулируют его. Повторный callback не удаляет повторно.
Удаление использует ту же блокировку аккаунта, что сбор и импорт сессии. Сначала
выключается автосбор, затем удаляется файл сессии под file lock и зависимые строки
БД в одной транзакции. При сбое очистки оставшаяся запись остаётся с выключенным
автосбором и неподтверждённым входом. Пустой .lock сохраняется для корректности flock.
Диагностические отчёты и исходный файл импорта вне рабочей сессии не удаляются.
Удалённый аккаунт снимается с планировщика без повторных попыток.

В рабочем коде Telegram-параметры используют aiogram enums: ParseMode.HTML,
ChatType.PRIVATE, ButtonStyle, FSMStrategy.USER_IN_CHAT. Allowed updates определяет
Dispatcher.resolve_used_update_types(); callback-действия — собственный AccountAction.
