# Диагностика и исследование

[← Документация](README.md)

Обычная работа выполняется в Telegram. Эти команды предназначены для разработки и разбора ошибок.
Диагностические отчёты сохраняются в `.secrets` и не должны попадать в Git или публичные issues.

| Команда | Назначение |
|---|---|
| `make login-qr` | Изолированный QR-вход; код выводится в терминал |
| `make login` | Резервный вход в локальном браузере |
| `make auth-check balance daily games` | Чтение через сессию `.secrets/cookies.txt` |
| `make diagnose-run RUN=<uuid>` | Диагностика операции из локальной БД |
| `make diagnose-daily ACCOUNT=<id>` | Текущий баланс и daily без начислений и изменения БД |
| `make diagnose-games ACCOUNT=<id>` | Чтение ответов игровых API выбранного аккаунта |
| `make emoji-preview` | Локальный каталог реального emoji-пака через Bot API |
| `uv run --no-sync python -m scripts.market --help` | Дополнительные инструменты ядра |

`ACCOUNT` — стабильный технический ID, не отображаемое имя аккаунта. Переименование его не меняет.
`SESSION` задаёт путь к файлу cookies для локальных команд, например:

```bash
make auth-check balance SESSION=.secrets/qr-login/run-example/cookies.txt
```

Для браузерных инструментов нужен extra `browser` (входит в `make sync`) и локальный Chrome/Edge
либо `uv run --no-sync playwright install chromium`.

## Архивное исследование эфиров

Модули `src/market/live.py`, `live_sources.py`, `inspection.py` сохранены как read-only
инструменты исследования. Их не вызывает бот или планировщик. Команды `live-probe`,
`live-status`, `live-report`, `live-sources`, `inspect-live` доступны через `scripts.market`.
Они не реализуют автоматический просмотр и не начисляют прогресс. Серверному запуску они не нужны.

> [!CAUTION]
> Пассивный браузерный инспектор и диагностика игр могут сохранять **полные ответы API**.
> Не прикладывайте raw JSONL, HTML, QR-ссылки или cookies к issue. Подготовьте минимальный
> обезличенный пример структуры вручную. Сохраняйте копию исходного отчёта приватно.

Подтверждённые контракты и нерешённые вопросы — в [исследовании API](api-research.md).

## Неопределённый результат начисления

Если операция завершилась `UncertainClaim`, автосбор останавливается. Не повторяйте claim
ради диагностики. Сначала получите журнал через `diagnose-run` и текущее состояние через
`diagnose-daily`. Второй скрипт сохраняет приватный JSONL, обновляет cookies из ответов,
но не меняет БД, расписание и `needs_review`.

Логи новых запусков различают `network_error`, `http_error`, `invalid_json`, `api_error`
и `invalid_object`, указывают HTTP-статус. `unknown` означает другую причину неопределённости,
например невозможность проверить состояние после запроса. Тип `UncertainClaim` в БД сохранён
для совместимости. Старые логи не содержат этих деталей, восстановить ответ задним числом нельзя.
Изменение баланса само по себе не доказывает, какая именно операция начислила монеты.
