# Матрица проверок

[← Документация](README.md)

> [!IMPORTANT]
> Успех unit-тестов не доказывает доступность внутренних API на другом аккаунте или IP.
> Логи пользователя и реальные запуски учитываются отдельно от тестов с подменой HTTP.

| Область | Подтверждение | Ограничение |
|---|---|---|
| Вход, баланс, daily, games, levels | Реальные запуски владельца 29.10.2026 | Контракты могут измениться |
| Daily до окончания таймера | Ответ unavailable, баланс без изменения | Успешное начисление требует проверки доступной награды |
| Игровые уровни | Реальный отчёт: 11 игр, 33 уровня | Положительное начисление заработанной награды отдельно не подтверждено |
| QR по HTTP | Вход, проверка API и чтение баланса | Один аккаунт и окружение |
| QR в Telegram | Владелец подтвердил успешный вход | VPS и длительность сессии ещё проверяются |
| Парсеры, доступ к боту, сессии, расписание, сервисы | pytest с fixtures / doubles / SQLite | Не live API и не реальный PostgreSQL |
| PostgreSQL | Реальный интеграционный тест прошёл в GitHub Actions 30.10.2026 | VPS проверяется отдельно |
| Docker | Сборка и smoke job прошли в GitHub Actions 30.10.2026 | Длительный запуск бота на VPS отдельно |
| Bash-установщик | ShellCheck, bash -n, тесты конфигурации/повторного запуска/защит | Чистый VPS пока не проверен |
| Эфиры | Только чтение/исследование | Автоматический сбор не реализован |

## Повторение проверок

```bash
make check
make test-postgres
```

`make check` не использует реальные credentials внешних API. PostgreSQL-тест по умолчанию
пропускается; `make test-postgres` включает его и работает во временной схеме существующей тестовой БД.
CI запускает его на отдельном PostgreSQL service container, без production-данных.
PNG-тест требует Pillow из `qrcode[pil]`; полный `make sync` устанавливает эту зависимость.

Перед первым production-релизом проверьте:

- [ ] Успешный CI и Docker smoke на GitHub, multi-platform публикацию в GHCR.
- [ ] QR-вход с IP сервера, сохранение сессии после перезапуска.
- [ ] Автосбор доступной daily по назначенному времени и запись результата в историю.
- [ ] Сбор положительной, реально заработанной игровой награды.
- [ ] Резервное копирование и восстановление на отдельной установке.
