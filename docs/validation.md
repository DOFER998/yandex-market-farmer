# Проверка 2026-10-29

Среда: macOS arm64, CPython 3.13.9; Linux не проверен.

- 65 pytest-тестов: успешны.
- ruff check и format --check: успешны.
- uv build --offline --no-build-isolation: wheel и sdist собраны.
- uv pip check: зависимости совместимы.
- Editable installation и ymf --help: успешны.
- Независимый обзор: исправлены потеря UncertainClaim при ошибке сохранения и нечисловые/бесконечные интервалы.
- Дополнительно устранены утечка cookie-строк в warnings и неявное использование proxy environment libcurl.

Синтетические фикстуры в tests/test_core.py основаны на Go-структурах; это не live-ответы.
Проверка транспорта охватывает конфигурацию настоящего curl_cffi.Session, но не TLS handshake,
Set-Cookie по сети или реальное начисление. Loopback bind в среде запрещён (PermissionError),
исходящий DNS терминала недоступен. Интеграционный тест не выдаётся за пройденный.

Зависимости восстановлены из ранее существовавшего кеша uv, не из сети. Для локальной установки
перепакованы кешированные wheel contents во временный каталог /tmp/ymf-wheels. Этот каталог не является
частью проекта; registry lock не подменён локальными wheel hashes. До deployment необходимо получить
uv.lock через обычный uv sync на машине с сетью и повторить проверки Linux.

Рабочие решения: sync-клиент с блокировкой, автоматический браузерный login с резервным Netscape import, отказ от игровых progress/result-вызовов, gate на реальные integration перед серверной частью.
Цена ограничений: потребуется интерактивный вход/проверка аккаунта; доступность всех игровых наград пока
не гарантирована. При неопределённом результате mutation клиент останавливается, но долговременного
журнала между процессами ещё нет — автономный сбор не запускать.

Добавлен Playwright login. Проверены конвертация HttpOnly/session cookies, фильтрация доменов/partitionKey,
ожидание возврата, отмена, закрытие браузера, сохранение старого jar и обработка ошибок без утечки.
Независимый обзор новых изменений не выявил важных дефектов. Реальный браузерный вход не запускался.

После пользовательской проверки: browser login сохранил сессию, но auth-check ошибочно
классифицировал ответ по любому упоминанию smartcaptcha/showcaptcha. Воспроизведена ложная
классификация синтетическим HTML со скриптом; заменена на активную форму, redirect path и title.
Это доказывает дефект детектора, но не доказывает отсутствие реальной CAPTCHA у пользователя.
Login теперь ждёт контекст авторизованной страницы, а не только cookie: окно остаётся открытым
при проверке/незавершённом переходе. Повторный live-запрос в среде агента дал TransportError.

Регрессия предыдущей правки: наличие всех API bootstrap-полей в browser DOM ошибочно стало
обязательным условием захвата. Пользователь сообщил о зависании на открытой странице колеса.
Тест с валидной cookie и страницей без bootstrap JSON воспроизвёл зависание (RED), после удаления
этого условия проходит (GREEN). Проверка API остаётся в auth-check, а не в browser login.
Это исправляет установленный дефект; реальный повторный вход пользователем ещё не подтверждён.

После сообщения ProtocolError: установлен дефект переноса appVersionRegex (первое поле
вместо первого desktop-совпадения). Регрессионный тест RED→GREEN; добавлены тесты диагностического
GET и отсутствия секретов в отчёте. Наличие этой ситуации в настоящем ответе пользователя пока
не подтверждено: агентский auth-check снова завершился TransportError. Для этого добавлен
безопасный diagnose-auth. Реальные значения версии/glue не подставляются из предположений.

По настоящей диагностике пользователя добавлен выбор единственного -version без desktop-маркера.
Проверены сохранение значения в исходящем HTTP-заголовке, отказ при неоднозначности и управляющих
символах. Реальный баланс с этим значением ещё не получен; синтетический тест не заменяет интеграцию.
