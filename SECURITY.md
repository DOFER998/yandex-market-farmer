# Безопасность

Проект хранит web-сессии Яндекса: cookies дают доступ к аккаунту. Файловые права `600/700`
ограничивают доступ другим пользователям ОС, но не шифруют содержимое диска.
Защита сервера, резервных копий и Telegram-аккаунта владельца остаётся вашей ответственностью.

## Секреты

Никогда не публикуйте `.env`, `.secrets`, cookies, QR-ссылки, track ID, токены, HAR и сырые
диагностические отчёты. Инструменты исследования могут сохранять полные ответы API.
Gitignore и Docker allowlist исключают локальные артефакты, но не очищают уже созданную историю Git.
Перед первым публичным push проверьте **все коммиты**, а не только текущие файлы.

Если сессия утекла — завершите соответствующие сессии в Яндексе и войдите заново.
При утечке токена Telegram перевыпустите его через BotFather, обновите `.env` и перезапустите бот.

## Сообщения об уязвимостях

Не открывайте публичный issue с секретами или воспроизводимым доступом к чужому аккаунту.
Используйте GitHub **Security → Report a vulnerability**, если владелец репозитория включил
private vulnerability reporting. Если пункт недоступен, запросите приватный канал связи у владельца
без публикации технических деталей эксплуатации.

Поддерживается актуальная стабильная версия. Срок исправления и работоспособность внутренних
API не гарантируются. Полный отказ от гарантий и описание назначения — в [README](README.md).
